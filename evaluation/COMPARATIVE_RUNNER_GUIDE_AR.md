# TRUTH ENGINE v4.1 — دليل مشغّل المقارنة

**النطاق:** تقييم نصي للبرومبتات عبر نقطة نهاية متوافقة مع Chat Completions. لا ينفذ المشغّل أدوات أو إجراءات خارجية ولا ينشئ وكلاء مستقلين.

## 1. ماذا يفعل المشغّل؟

يرسل كل مُدخل ثابت من ملف JSONL إلى ثلاثة شروط باستخدام **النموذج نفسه**:

- `BASE_MODEL`: دون رسالة نظام خاصة بـ TRUTH ENGINE.
- `V4_0`: البروتوكول الكامل v4.0 باللغة الإنجليزية أو نسخته العربية وفق لغة الاختبار.
- `V4_1_CANDIDATE`: البرومبت الرئيسي v4.1 مع الوحدات الخمس ذات الصلة باللغة الإنجليزية أو العربية.

يحفظ المخرجات الخام محلياً وينشئ نسخة منفصلة من مصفوفة التشغيل بعد تعبئة بيانات التنفيذ. ولا يملأ الدرجات أو أحكام المقيمين.

## 2. المتطلبات

- Python 3.10 أو أحدث؛ المشغّل يستخدم المكتبات القياسية فقط.
- نقطة نهاية متوافقة مع OpenAI وتدعم `POST /chat/completions`.
- صلاحية وميزانية لتشغيل النموذج المطلوب.
- بصمة Git commit ثابتة للملفات التي يجري اختبارها.

توثق مرجعية OpenAI واجهة `/chat/completions` وتوصي بـ `max_completion_tokens` بدلاً من `max_tokens` الذي أصبح قديماً؛ وقد يختلف دعم المعلمات بحسب النموذج. المرجع: https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create

## 3. إعداد الأسرار خارج المستودع

اضبط متغيرات البيئة في الطرفية التي ستنفذ الاختبار:

```bash
export TRUTH_ENGINE_API_BASE="https://YOUR-ENDPOINT/v1"
export TRUTH_ENGINE_API_KEY="YOUR_SECRET_KEY"
export TRUTH_ENGINE_MODEL_ID="YOUR_PINNED_MODEL_ID"
export TRUTH_ENGINE_PROVIDER="اسم المزود أو بيئة النشر"
export TRUTH_ENGINE_TESTED_COMMIT_SHA="40-character-git-commit-sha"
```

لا ترفع مفتاح API إلى GitHub، ولا تضعه في CSV، ولا تنقله إلى قضايا أو سجلات عامة. يرسل المشغّل مُدخلات اختبار اصطناعية ونصوص البروتوكول فقط. احفظ المخرجات الخام محلياً في مسار محمي.

## 4. ابدأ بالفحص الجاف

من جذر المستودع:

```bash
python scripts/validate_v4_1_docs.py
python scripts/run_comparative_eval.py --dry-run --limit 6
```

يجهز الفحص الجاف أول ستة طلبات (ثلاثة شروط لحالة مزدوجة واحدة باللغتين)، ويعرض أطوال المدخلات والبرومبتات وبصمات برومبت النظام. لا يجري اتصالات شبكية ولا يحتاج مفتاح API.

## 5. تشغيل مقارنة صغيرة

شغّل الحالة الأولى باللغتين وتحت الشروط الثلاثة:

```bash
python scripts/run_comparative_eval.py \
  --case-id TE41-01 \
  --languages EN,AR \
  --output-dir "$HOME/truth-engine-v4.1-smoke"
```

يرسل هذا ستة طلبات. افحص قبول نقطة النهاية وحدود السياق ومعرّف النموذج المسترجع والاستخدام والزمن والمخرجات الخام قبل تشغيل مجموعة أكبر.

## 6. تشغيل مصفوفة 162 خانة كاملة

بعد مراجعة المقارنة الصغيرة:

```bash
python scripts/run_comparative_eval.py \
  --output-dir "$HOME/truth-engine-v4.1-full-run"
```

ينشئ ذلك 162 خانة مقارنة: 25 حالة مزدوجة × لغتين × ثلاثة شروط، إضافة إلى أربع حالات عربية أصلية × ثلاثة شروط. تتطلب خانات TE41-19 وTE41-25 الاثنتا عشرة تبادل طلبين متتابعين لكل خانة، لذلك يرسل التشغيل الكامل لمرة واحدة 174 طلباً إلى نقطة النهاية. قد تترتب تكلفة من المزود. لا يخمن المشغّل التكلفة ولا يملأها عندما لا يقدمها المزود.

استخدم لقطة النموذج نفسها وإعدادات التشغيل نفسها في الشروط الثلاثة. يستخدم المشغّل `max_completion_tokens` افتراضياً. لنقطة نهاية متوافقة تشترط الحقل الأقدم، استخدم `--token-field max_tokens`. إذا لم يدعم النموذج درجة الحرارة فاتركها غير محددة؛ وإذا كان يدعمها وحددتها مسبقاً، فاستخدم القيمة نفسها في كل الشروط. لا تخلط الإعدادات دون توثيق.

## 7. التحكيم اليدوي والتلخيص

يحتوي مجلد النتائج على:
- `raw/`: سجل JSON لكل إجابة منفذة، ويتضمن المدخل والمخرج ومعرّف النموذج المسترجع والاستخدام والزمن وcommit SHA وبصمة برومبت النظام.
- `COMPARATIVE_RESULTS.csv`: نسخة من مصفوفة التشغيل محدثة ببيانات التنفيذ وروابط محلية للمخرجات الخام.

يقيّم النتيجة مقيمان اثنان باستخدام مفاتيح التحكيم وقاموس البيانات. املأ `score_0_2` وعلامات الإخفاق والمقاييس المنطبقة فقط على الحالة. الخانة الفارغة تعني «غير منطبق/لم يُقيّم»، ولا تعني صفراً.

ثم احسب الملخص:

```bash
python scripts/summarize_comparative_runs.py \
  --input "$HOME/truth-engine-v4.1-full-run/COMPARATIVE_RESULTS.csv" \
  --output "$HOME/truth-engine-v4.1-full-run/COMPARATIVE_SUMMARY.csv"
```

الملخص وصفي؛ ولا يحكم على الإجابات ولا يثبت الدلالة الإحصائية.

## 8. قيود مهمة

- يختبر المشغّل السلوك الناتج عن البرومبت عبر نموذج واحد. لا يثبت استقلال وكلاء حقيقيين، ولا إنفاذ صلاحيات الأدوات، ولا أمان الإجراءات الخارجية، ولا الأمن على مستوى التطبيق ضد حقن التعليمات.
- لا يمكن ادعاء تحقق التقييم الأولي المعمى في TE41-10 إلا إذا نفذت بيئة التقييم سياقات منفصلة وحفظت المخرجات الأولية فعلياً؛ المشغّل لا يوفر ذلك.
- لا يجلب المشغّل مصادر حية. استخدم الوقائع والمقتطفات المجمدة في ملفات الاختبار.
- ينفذ محاولة واحدة لكل خانة. تحتاج التجارب المتكررة إلى نسخ الصفوف بأرقام تجارب فريدة مع الاحتفاظ بالمدخل والإعدادات نفسها؛ لا تكتب فوق نتائج سابقة.
- قد تتغير أسماء النماذج الرمزية. استخدم لقطة ثابتة متى أمكن واحفظ معرّف النموذج المسترجع وcommit SHA بدقة.
- نجاح استدعاء API لا يعني اجتياز الحالة. ما زال التحكيم البشري والاختبار المحجوب مطلوبين.
