# Source Gap Matrix — TRUTH ENGINE v4.1

**Status:** Comparative design record. v4.0 remains the baseline. This document distinguishes material already present in v4.0 from material that needs operational specification. It does not claim benchmark improvements.

## Sources compared

- The complete v4.0 Arabic protocol and the current English protocol in the public repository.
- The attached Arabic file named `TRUTH_ENGINE_v4.0_UNIVERSAL.md`, which is an earlier Arabic variant despite its English-looking filename.
- `TRUTH ENGINE(1).txt` and `TRUTH ENGINE.txt`, which are duplicate v3.1 copies in the supplied set.
- `TRUTH ENGINE v3.txt`, a materially different v3.1 copy with weaker permission and action-approval safeguards. Its provenance is unknown; it is quarantined and not used as a source.
- `تطوير بروتوكول الحقيقة.md`, a development memo containing the proposed Master Prompt 2.0. It is a proposal, not evidence that a historical released product called v2.0 existed.

## Gap classification

| Source idea | v4.0 status | v4.1 work |
|---|---|---|
| Constructive critical partnership and anti-sycophancy | Present | Preserve and test behaviourally |
| Cognitive-bias register | Present, broader register | Test important bias families rather than only list names |
| Atomic claim decomposition | Partial | Standard Claim Ledger with IDs, statuses, scope and evidence links |
| Source taxonomy | Incomplete | Record primary, secondary, tertiary, anecdotal or unverified type; type is not quality |
| Six-question source integrity check | Scattered | Consolidate existence, originality, entailment, date, independence and caveats |
| Blind independent assessment | Principle present | Define isolated first-pass workflow and record when isolation is impossible |
| Four distinct functions (analyst, adversarial auditor, fact verifier, adjudicator) | Some functions combined | Separate responsibilities without requiring four running models |
| Falsifiability testing | General principle | Hypothesis record, predictions, falsifiers, alternatives, discriminating test and predeclared criteria |
| Evidence quality | Partial and distributed | Describe directness, reliability, independence, consistency and freshness without arbitrary composite scores |
| Confidence / verification coverage / residual uncertainty | Not sufficiently separated | Keep as distinct fields; confidence is not coverage |
| Epistemic vs decision layer | Partial | Prevent recommendations from rewriting factual findings |
| Metrics and denominators | Broad metrics exist | Define computation and reportability conditions |
| Modular architecture | Proposed, not implemented in v4.0 | Separate core, evidence, agent/security, uncertainty/decision and evaluation modules |
| Domain-specific profiles | Not present | Optional profiles, only after domain-specific review |
| 70 finalized benchmark cases | Not present; only category counts | Start with pilot cases, then build a validated and held-out set |
| Paired English/Arabic evaluation | General cross-platform guidance only | Add paired translations and native-language cases |
| High-stakes decision cases | General caution present | Dedicated cases and review criteria |
| Monthly audit | Suggested in the memo | Defer cadence until operational runs and data exist |

## Existing v4.0 material to preserve, not duplicate

The seven-layer architecture; instruction hierarchy and capability limits; anti-sycophancy; source checking and temporal validity; reasoning, logic, mathematics and causality; adaptive debate; simulated vs multiple-call vs actual multi-agent distinctions; agent operating contract; uncertainty and abstention; prompt-injection and tool security; high-impact decision safeguards; change control and evaluation discipline.

## Language decision

English is the normative authoring source for shared requirements. Arabic is an official translation subject to semantic parity review—not a separate policy fork. Users should still interact in their preferred language. No universal performance advantage is assumed for English; paired testing is required.

## Release caution

The v4.1 work is a development candidate. No improvement is claimed until the same controlled cases are run against baseline and v4.0, with model, date, tools, settings, language, cost and failure data recorded.
